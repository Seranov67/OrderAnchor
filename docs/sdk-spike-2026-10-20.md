## Hash before sending

signPlacement receives explicit chain/nonce/gas/fees and a local account, signs the exact POST_ONLY placeOrderFor payload and returns keccak256(serializedTransaction). It has no RPC or transport. Tests recovered the signer, changed the nonce to obtain a different hash and rejected wrong signer/payload.

Spike fixtures used random unfunded in-memory keys and deliberately expired orders. They were not user wallets. Keys and signed bytes were not published; private test databases stayed under ignored tmp. No fixture transaction was sent.

The operator ABI came from the [official bot kit, commit 25798660bbe4674a6f83a960b202852896e2fed4](https://github.com/somnia-chain/dreamdex-bot-kit/blob/25798660bbe4674a6f83a960b202852896e2fed4/packages/perp-core/src/operator.ts). MIT notices are retained. Encoding/decoding confirmed selectors 0x80054449 and 0xe37b444b; POST_ONLY=3. The exported SDK perpPoolWriteAbi had owner calls but not these For methods.

## What the SDK already provides

The installed SDK has TransactionOutcomeUnknownError carrying a hash. Its local executor has an in-memory nonce lane and sequential sends within the owning engine. It locally signs EIP-1559, uses raw sending and waits for a receipt. It would be inaccurate to claim that the SDK ignores unknown outcomes or nonce management.

OrderAnchor uses its own executor to commit signed bytes/hash durably before transport and recover after process termination. The reviewed built-in sending verbs waited for receipt before returning and exposed no durable pre-broadcast callback into our store. The SDK also provides buildPlacePerpOrder and a custom executor seam for owner calls; this prototype encodes the operator path from the official ABI.

## Initial core at this historical checkpoint

- Protocol validates raw units, addresses and chain; encodes exact POST_ONLY/cancel. Preflight rejects silent decimal rounding and checks tick/lot/min plus typed account/permission/maximum reads.
- Signing is local and verifies chain, signer, payload and hash.
- SQLite v2 had intents, transactions, events and observations. Intent/signature/event commit together; one unresolved signer and an EXCLUSIVE lifetime writer lock. Unknown/corrupt/missing databases are not silently replaced.
- Executor commits UNKNOWN before one transport attempt. A response error stays unknown; no automatic resend. A failed database commit never reaches transport.
- Read-only reconciliation checks hash/sender/chain/nonce/target/input/value, canonical confirmations and exact OrderPlaced. Null/insufficient confirmations/malformed known events stay unknown; wrong identity conflicts. Unavailable RPC never upgrades cached state into fresh proof.
- CLI supported inspect-market, status and read-only resume; no live place/cancel command.
- Offline CI was prepared without secrets, but had not run on GitHub. Local success is a separate fact.

## Historical limits

Cancellation journaling/execution, current remaining/position accounting, export/verifier and terminal lifecycle were not yet integrated. CONFIRMED meant a checked placement receipt/order identity, not a fully checked current order. The writer guard remained after confirmation. Reorgs involving a previously reverted record and a newly opened intent required additional policy/tests.

Offline signatures were not permission to broadcast. Real owner/signer, funding, permissions, authoritative market checks, simulation, gas budget and restrictive key/database ACLs were prerequisites. Gitignore is not a substitute for filesystem access control.

## Reproduce

```powershell
npm.cmd ci --ignore-scripts --no-audit --no-fund
npm.cmd run typecheck
npm.cmd test
npm.cmd run spike:offline
npm.cmd run probe:market -- ETH
npm.cmd run probe:receipt
npm.cmd run cli -- help
```

npm ci downloads packages. The offline spike/tests never broadcast fixture transactions; the probe commands only read. Receipt probing first needs a successful ETH market snapshot.

Twenty local tests at this checkpoint covered real SQLite, ID uniqueness, second-writer exclusion, rollback before send, unknown/reorg/conflict, malformed known logs and actual child exit after mock acceptance but before transport returned. Reopen retained the hash without a second send; a pre-send kill was also checked. This was not yet live A2. Later reports document funded G3/G4 execution.
